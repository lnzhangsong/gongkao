# 读本 READBOOK · 产品埋点设计方案（PostHog）

> 状态：**设计稿**（待确认后实施）
> 起草日期：2026-09-07
> 背景：项目尚无真实用户，需要在推广前先能回答「有没有人用、从哪来、用哪些功能、在哪一步流失」。经方案比选（Vercel Analytics / Umami / GA4 / 百度统计 / Plausible / PostHog / 自建），**用户已裁定选 PostHog 云**。
> 原则：**不采集任何个人身份信息**（不传邮箱/昵称/正文内容/笔记内容）；埋点失败绝不影响主功能。

---

## 一、要回答的问题（埋点的验收标准）

| # | 问题 | 需要的数据 |
|---|---|---|
| Q1 | 有没有人来？从哪来？ | PV/UV、referrer、设备 |
| Q2 | 来了用不用？用哪块？ | 各页面停留与功能事件计数（阅读/摘录/申论/真题/ASSIST） |
| Q3 | 账号链路通不通？ | 注册/登录/退出计数、同步成功率 |
| Q4 | AI 功能有没有人真的在用？ | 各 AI 动作的触发次数与成功率 |
| Q5 | （后续）答题卡落地后的转化 | 「打开题目 → 写答案 → 完成」漏斗 |

Q1-Q2 靠自动采集，Q3-Q5 靠一组人工埋点事件（下文 §三）。

## 二、接入设计

### 2.1 技术形态

- 依赖：`posthog-js`（官方前端 SDK，~20KB gzip，懒加载不阻塞首屏）
- 初始化：`src/lib/analytics.ts` 封装，App 挂载时 `posthog.init(KEY, { autocapture: false, capture_pageview: 'history_change', ... })`
  - **autocapture 关闭**：全量 DOM 自动采集噪声大且可能带敏感文本，只走白名单事件
  - SPA 路由 pageview：history 模式自动上报，无需手动埋
- **国内访问与去广告拦截：反向代理（关键项）**
  - 默认 SDK 直连 `us.i.posthog.com`，国内直连慢且易被广告插件拦
  - 方案：`vercel.json` rewrites 加 `/ingest/* → https://us.i.posthog.com/*`，SDK 的 `api_host` 设为自身域名 `/ingest`——请求走自己域名（同站、同 CDN），既绕广告拦截又无新增被墙面
  - 此为 PostHog 官方支持的反代方式，Vercel 文档有现成配置

### 2.2 身份策略

- **匿名优先**：不调 `identify`，所有事件挂在 PostHog 匿名 id（cookie/localStorage）上
- 登录后调 `posthog.identify(<supabase user id>)`——只有一串无意义的 uuid，**不传邮箱/昵称**；这样能区分「匿名浏览」与「注册用户」两条曲线，且同设备先匿名后登录能归并为同一个用户
- 不采集：文章正文、摘录/笔记内容、AI prompt 与生成全文、API key（当然）。事件 props 只允许 id 类（articleId/paperId）、枚举类（题型/主题/成败）与数值（字数等）

## 三、事件清单（白名单，先少后多）

| 事件 | 触发点 | props |
|---|---|---|
| `pageview` | SDK 自动（路由变化） | — |
| `auth_login` | 登录成功 | method: password/magic_link |
| `auth_logout` | 退出确认 | — |
| `sync_done` / `sync_error` | 云同步轮次结束 | duration_ms / error 表名 |
| `article_read_finish` | 进度达 95%（articleStore 已有判定点） | articleId, topic |
| `annotation_add` | 新增高亮/下划线/笔记 | kind, articleId |
| `shenlun_deconstruct` | 拆解保存 | articleId |
| `exam_trace` | M1 思路推导保存 | paperId, qIdx, origin |
| `assist_generate` | AI 审题框架/完整出题成功 | mode: framework/full_exam, questionType |
| `answer_write` / `answer_check` | 答题卡 P1/P3 落地后接入（预留） | paperId, qIdx |

埋点点位多数是**现有动作处加一行**；`article_read_finish`、`exam_trace`、`assist_generate` 的触发位置在 store/页面里都已存在，无需新逻辑。

## 四、成本与限额

| 项 | PostHog 云免费档 | 本项目现状 |
|---|---|---|
| 事件量 | **100 万/月** | 假设日活 100 人 × 50 事件 ≈ 15 万/月，余量充足 |
| 数据保留 | 1 年 | 足够；重要的聚合结论定期自己导出 |
| 超量 | 不会自动扣费（提示后需手动升级） | 安全 |

## 五、分期

| 期 | 内容 |
|---|---|
| **E1 基础接入** | SDK + 反向代理 + pageview + 自动采集关闭 + `auth_login/logout`；上线当天即可回答 Q1/Q3 |
| **E2 功能事件** | §三 全部白名单事件埋点；回答 Q2/Q4 |
| **E3 分析面板** | 建看板：周活趋势、功能使用分布、登录转化；答题卡上线后加漏斗（Q5） |

E1+E2 合计改动约 **150–250 行**（一个封装文件 + 十余处单行埋点 + vercel.json 一条 rewrite）。

## 六、风险与回退

| 风险 | 缓解 |
|---|---|
| PostHog 云国内加载慢 | §2.1 反代走自己域名；SDK 懒加载，最坏情况埋点静默失败、主功能零影响 |
| 广告插件拦截 | 同上，反代同域后绝大多数拦截规则不再命中 |
| 免费额度政策变化 | 事件白名单克制；封装集中在 `analytics.ts`，换供应商（如 Umami）只改一个文件 |
| 隐私合规 | 不传 PII；文档明示；如需彻底自持数据，未来可平移 PostHog 自托管或 Umami |

## 七、待确认

1. PostHog 项目注册在**美区云**（免费额度）还是欧区——建议美区（与 Vercel 默认区一致，反代延迟最低）
2. E2 事件清单有无要增删（特别是：要不要埋「搜索关键词」？有用但属于用户输入内容，默认不埋）
