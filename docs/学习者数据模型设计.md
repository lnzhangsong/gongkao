# 读本 READBOOK · 学习者数据模型设计

> 状态：**理念稿**（与 `数据飞轮与壁垒设计.md` 配套：飞轮文档解决"数据沉淀与回流"，本文解决"沉淀下来的数据如何统一为一个学习者模型"）
> 日期：2026-09-05
> 核心主张：**掌握度是推导出来的输出，不是用户手动申报的输入。**

---

## 一、问题：五座孤岛

产品目前已积累五份学习数据，各自独立成 store，仅靠 `articleId` 松散关联：

| # | 数据 | Store | 掌握口径 |
|---|---|---|---|
| 1 | 文章级学习（状态/星级/核心观点/骨架/段意） | `shenlunStore` | `StudyStatus` 三态 + `mastery 0-3` 星 |
| 2 | 素材级学习（素材类型/背记/掌握度） | `annotationStore` | `mastery 0-2` 三点 + `memorized` 布尔 |
| 3 | 真题学习（要点加工/材料标注） | `examStudyStore` | **无掌握概念** |
| 4 | AI 辅助记录（出题/审题立意） | `aiAssistStore` | 无 |
| 5 | 阅读行为（时长/进度） | `articleStore.progress` | 无 |

病根不在字段缺失，而在**没有"学习者模型"这个概念**：五份数据本质上都在回答同一个问题——学习者对某个知识对象掌握到什么程度——却被三套互不相通的口径各说一遍。由此产生一系列症状：

- 写完核心观点、做完段意拆解，文章状态仍是"未学"（状态全靠手动）；
- 素材标了背记、点了掌握，文章星级不感知（素材级与文章级不通）；
- 在真题页认真加工过一道以某篇范文为底本的题——这是"真的会了"最强的证据——却完全不回流到任何掌握度上（输出端断裂）；
- 所有掌握状态都是**快照**：没有"何时证明过、是否退化"的时间维度，"已掌握"存进去就永远是真的。

## 二、三个理念

### 理念 1：证据模型，而非申报模型

用户做的每个动作都是对某个掌握对象的一次**证据采集**。读完一篇、写一段段意、标一句背记、答一道题、AI 反向出题检验——这些动作天然发生，掌握状态由证据**推导**得出，而不是要求用户在某个面板里手动申报。

用户保留的只有**否决权**：可以手动把状态钉在任意一档，推导引擎尊重钉住的值（钉住 = 不再自动升降，直到用户解除）。这与飞轮文档的不变式同构："AI 生成候选 → 人工确认"，掌握度同理："引擎推导候选 → 人工可否决"。

### 理念 2：掌握对象只有三层，学习闭环只有一个

申论学习的对象本质上只有三层：

```
能力层（会答题吗）        ← 真题答题、AI 出题检验、大作文
   ↑ 检验
文章层（懂这篇范文吗）    ← 阅读进度、拆解（核心观点/骨架/段意/心得）
   ↑ 支撑
素材层（金句句式能调用吗）← 标注、背记、掌握度自评、模板填写
```

学习闭环：**输入**（精读）→ **内化**（拆解、背记）→ **输出**（答题/写作）→ **检验反馈**（对照参考答案、反向出题）→ 回到内化。

当前闭环断在输出端：真题线（examStudyStore）与 AI 出题（aiAssistStore）是产品里"证明学会"权重最高的数据，却与文章/素材的掌握度零回流。融合的第一优先级是把输出端接回来，而不是给输入端再加自动联动。

### 理念 3：快照 → 事件流

"已掌握"是一个会衰减的状态，对背记类素材尤其如此。模型上必须从"最后一次点成什么样"（快照）转为**至少记录关键事件的时间戳**：

- `evidencedAt`：最后一次有效证据的时间；
- `reviewCount`：检验次数。

有了时间维度，"N 天未复习的已掌握素材"、"本周有产出的文章"才成为可计算的概念，间隔重复（ReviewModal 翻转卡、遗忘曲线）只是事件流之上的视图，不是独立功能。

### 理念 4（2026-09-05 增补）：使用即复习，不为复习造仪式

备考者没有"专门复习"的时间与心态，独立复习入口注定低使用率。记忆增强发生在"提取"那一刻——那就把提取织进用户本来就要做的动作里，让复习从功能降格为所有功能的隐藏属性：

| 嵌入点 | 形式 | 状态 |
|---|---|---|
| AI 作答框架生成 | 召回排序按可提取概率升序（回声排序）：快忘的素材排前，更易被 AI 挑进框架——用一次即复习一次 | ✅ 已实现 |
| 框架保存 | 挂进要点的素材回写 `material-use` 证据（权重 4，素材类最强） | ✅ 已实现 |
| 真题作答要点加工 | 从素材库插入候选，插入即调用 | 第 3 期埋点已就位，候选 UI 待做 |
| 大作文写作引用 | 引用素材/骨架 = 终极证据 | 未开始 |
| ReviewModal 翻转卡 | 降级为摘录页可选入口，服务有复习习惯的用户 | ✅ 已实现（可选） |

产品原则：**不弹窗、不红点、不设任务量**。复习的意义在自愿提取，不在完成率。

## 三、目标模型

### 3.1 数据形态

不新建大一统 store，而是**约定口径 + 派生层**：

```
五个现有 store（证据源，保持本地优先与现有 schema 兼容）
        ↓  采集：只追加，不改写
learntEvents（轻量事件流水：{ objectId, objectType, kind, weight, at }）
        ↓  推导：纯函数，可缓存
LearnerProfile（三层掌握状态 + 最近证据时间，供首页/文库/复习视图消费）
```

- 现有 store 继续作为**可编辑快照**（用户手填的拆解内容、标注本体不动）；
- `learntEvents` 只记录"发生了什么"，是新增的唯一 schema（IndexedDB，persist 迁移仅为新增 key，无破坏性）；
- 推导纯函数放 `lib/`，输入事件流与快照，输出三层状态，无副作用、可测试。

### 3.2 证据类型与权重（初版建议）

| 动作 | 对象层 | 权重 | 说明 |
|---|---|---|---|
| 完成阅读（percent ≥ 95） | 文章 | 1 | 最弱证据：读过 ≠ 懂了 |
| 写核心观点 / 段意 / 骨架 | 文章 | 2 | 主动加工 |
| AI 拆解被采纳/编辑 | 文章 | 2 | 走人工确认才计数（不变式） |
| 写学习心得 | 文章 | 3 | 复盘性质 |
| 标注为素材 | 素材 | 1 | 圈选即存 |
| 加入背记 | 素材 | 1 | |
| 掌握度自评 ● / 翻转卡答对 | 素材 | 2 | 未来 ReviewModal 的产出 |
| 真题要点加工（一道题完成） | 能力 + 关联文章 | 4 | 最强证据，双向回流 |
| AI 反向出题存题并作答 | 能力 + 关联文章 | 3 | |
| 大作文引用某素材/骨架 | 素材/文章 | 4 | "用出来"是终极证据 |

权重数值是理念示意，落地时应以"达到『学习中』『已掌握』各需何种证据组合"的规则表为准（如：文章层 = 任一权重 ≥2 证据 → 学习中；+ 心得或输出端证据 → 已掌握候选；+ N 天后仍能复述（复习事件）→ 已掌握确认）。

### 3.3 与现有三套口径的归并

- `StudyStatus`（new/learning/mastered）：保留为文章层推导结果，字段不动，语义变为"推导值 + 用户钉住标记"；
- `mastery` 星级（文章）与三点（素材）：理念上属于自评证据，降级为**证据的一种**而非状态本身，UI 上仍可保留手动点选；
- `memorized`：保留，作为素材层"进入复习池"的开关。

## 四、掌握度算法选型（2026-09-05 增补）

候选与取舍：

| 算法 | 原理 | 为何（未）选 |
|---|---|---|
| **FSRS**（DSR 模型） | 幂律遗忘曲线 R(t)=(1+t/(9S))^(−2)，难度/稳定性/可提取性三参数 | 实测最优的开源间隔重复算法。完整版需逐次「对/错」评分历史，当前只有时间戳+自评，**取其曲线、简化其输入**（已实现） |
| SM-2（Anki 经典） | 固定间隔调度 + 4 档评分 | 需要定期调度，与「使用即复习」的非定期提取不匹配 |
| Half-Life Regression | 记忆半衰期回归模型 | 需要批量训练数据，单机场景无从拟合 |
| DASH / Duolingo 模型 | 按练习时间间隔预估正确率 | 同样依赖固定练习流 |

**落地（`src/lib/mastery.ts`）**：FSRS-4.5 幂律遗忘曲线的简化版——稳定性 S 按当前自评掌握度取初值（0/1/2 星 → 3/6/15 天），每条 `material-use` 证据让 S×1.3（封顶 5 次），输出素材级可提取概率 R∈(0,1]。

**定位**：不是调度器，是**排序器**。R 用于回声排序（AI 召回时快忘的排前）与到期计算，不驱动任何弹窗或任务列表。

**升级路径**：若翻转卡/回声开始收集「想起/没想起」二元评分，即可平滑升级为完整 FSRS 参数拟合（逐用户本地拟合，仍是本地优先）。

## 五、迁移与分期

**原则：先立口径，后动 schema；每期都可独立交付、独立回滚。**

- **第 0 期（理念定稿）**：本文档评审定稿，确认证据规则表与否决权交互。
- **第 1 期（事件采集）**：新增 `learntEvents`，在现有各写路径埋点追加事件；不改变任何现有 UI。
- **第 2 期（推导上线）**：`LearnerProfile` 推导 + 文章状态自动推进（含钉住交互）；首页统计改读推导层。
- **第 3 期（输出端回流）**：真题答题、AI 出题作答事件双向回流到文章/素材层。
- **第 4 期（使用中强化，2026-09-05 修订）**：~~独立的复习视图~~ → 掌握度算法（`mastery.ts`）+ AI 框架召回回声排序 + `material-use` 证据回写；ReviewModal 翻转卡与首页"今日复习"降级为可选入口，服务有复习习惯的用户。后续嵌入点见理念 4 的表格。

第 2 期之前用户无感知；任意一期停下，系统都处于自洽状态。

## 六、不做的事

- **不做大一统 store 重写**：Repository 层架构本就为换数据层准备，融合走派生层而非搬家；
- **不做全自动覆盖**：推导永远给用户留否决权，对齐"AI 候选 → 人工确认"不变式；
- **不引入云端账号体系**：本地优先不变，事件流同样存 IndexedDB，随导出/导入 JSON 跨设备（需同步加入导出格式，见第 1 期）；
- **不做精确遗忘曲线**：初版只有时间戳与简单衰减，SRS 算法属于第 4 期之后的演进，不提前设计。

## 七、输出端：需要，但形态待定（规划，暂缓）

> 2026-09-06 记录。结论先说：**输出是要做的，但不是现在，也不以「写作功能」的形态混进读本。**

### 背景

- 学习闭环的输出端目前是断的：AI 辅助只"搭架子、备好料"，真题页没有自己的作答流。证据表里权重最高的类型（`material-use`、`exam-answer`）几乎不产生真实数据，推导层只能靠弱证据猜测"会不会"。
- 但读本的根是**精读工作台**——读、标、拆、存。曾试过在已存框架下直接挂"成文写作"textarea，已撤销：那等于把写作工具塞进阅读工具，背离产品性质。

### 将来考虑输出时的边界与候选形态

1. **边界原则：读本不变成写作产品。** 输出若是独立模块（独立入口/页面，与阅读线平行），可以；若长在阅读流和拆解面板里，不行。届时先在本文档评审形态，再动代码。
2. **候选形态（未定，按侵入性从低到高）**：
   - **真题页作答流**：材料/题目/参考答案之外加"我的作答"，写完对照。最接近"真题"这个既有模块的语义，改动局限在 exams 线；
   - **独立"作答本"页面**：从框架或题目发起，写作区独立于阅读流，产物随导出 JSON 走；
   - **只导不写**：框架/题目一键导出为 Markdown 骨架，写作发生在外部工具，回流仅凭用户手动挂接（最轻，但证据最弱）。
3. **无论哪种形态，数据侧已就绪**：事件层加一类输出证据即可（复用 `material-use` / `exam-answer` 口径），回声排序与推导层零改动。
4. **算法侧的触发点**：输出数据积累起来后，能力层的掌握度估计启动（BKT / Elo 式评级，见「四、掌握度算法选型」），素材/文章层不受影响。

### 经验教训（本节存在的理由）

功能冲动来自"闭环缺输出端"的推演，判断是对的，但**落点错了**——缺的是输出数据，不是阅读产品里的写作框。先把数据模型和证据口径立住（本文档 1–4 期），输出端等形态想清楚再接，接的时候应该很快。
