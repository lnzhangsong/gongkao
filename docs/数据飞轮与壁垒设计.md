> 状态：**设计稿**（与 `申论功能整合新方案.md` P1-P7 / `申论写作AI辅助设计方案.md` AI-1~AI-4 配套，作为壁垒演进的顶层设计）
> 日期：2026-08-31
> 关联需求：把“单机工具的执行力壁垒”升级为“数据飞轮的结构性壁垒”

---

## 一、为什么现在壁垒薄

| 维度 | 现状 | 结论 |
|---|---|---|
| 内容 | 517 篇年编 + 12 主题 + terms/exams 人工清洗，随部署打包，只读分发 | 有整理成本，但原文无版权独占，可被爬/可被抄 |
| 行为数据 | 标注/拆解/背记全在 `IndexedDB/localStorage`，单机闭环，不回流 | 无数据沉淀，无网络效应 |
| 切换成本 | 一键导出 JSON，导入即迁移 | 零锁定 |
| AI | BYOK 本地组装 prompt，服务端纯转发，不沉淀 | 通用提示词，换个壳就能复刻 |

**一句话：** 现在是“静态库 + 单机工具”，抄的是时间，不是门槛。

---

## 二、飞轮总览

以“**读得越多 → 标得越准 → AI 越懂你 → 写得越快 → 供得越新**”为顺时针方向，三层嵌套：

```
原料飞轮（供给侧）          加工飞轮（用户侧）          智能飞轮（AI 侧）
日更/周更入库 ──┐          选中即素材(5类) ──┐        预拆解候选 ──┐
     ↑          │               ↑           │             ↑         │
  精选回流 ◄────┘          段意/骨架/句式 ◄┘        人工确认入库 ◄┘
     │                     素材合集导出              反向考点联想
     └────────── 人机协同沉淀 ──────────┴────────── 模板/考点库 ──┘
```

**不变式：** 全链路 `AI 生成候选 → 人工确认 → 入库`，不自动覆盖用户手填内容。

---

## 三、三层飞轮分述

### 3.1 原料飞轮（Content Supply Loop）

- **输入：** 人民日报日更/周更、用户外源文件 `scripts/import-*.mjs → data/articles.db`、真题 `exams`、规范词 `terms`
- **加工：** 统一 Schema（title/summary/content[]/source/topic/date/pullquote），API 只读分发 `/api/articles`
- **回流：** 运营精选“本周必读 10 篇 + 拆解样张 + 句式模板”回写入库，下一批用户直接受益
- **指标：** 周更篇数、入库→可读可用时长 <24h、精选采纳率

### 3.2 加工飞轮（User Processing Loop）—— 已半闭环

- **能力：** `annotationStore`（highlight 6 色/underline 4 式/note 富文本 + `materialType` 5 类）+ `shenlunStore`（核心观点/分论点/心得 + `paragraphSummaries`/`skeleton` D15）+ `offsets.ts` 全局偏移
- **沉淀：** 摘录页聚合、Markdown 合集导出（论点→论据→金句→对策→句式，句式带 原句→模板）、`readbook:shenlun` 整包导入导出跨设备
- **当前断点：** 加工完就停在本地，未回流。需补“**个人飞轮历史复用**”（见 3.4 阶段一）与“**众包回流**”（阶段三）

### 3.3 智能飞轮（AI Assist Loop）—— BYOK 起步

- **正向：** 题干 + 主题过滤后的素材 + 拆解记录 → 审题立意/作答框架（AI-1/AI-2），每项挂素材卡片
- **反向：** 文章/素材 → 考点/题干联想 L1 → 完整出题 L2（AI-4/AI-4+），确认后存 `aiAssistStore`，与素材双向跳转
- **预拆解：** 一键生成 5 类标注候选 + 段意/骨架/句式模板候选（AI-3/D15），人工逐条确认后反哺素材库
- **演进：** 素材 <1k 条时关键词匹配直塞 prompt 即可；>数千条或跨主题召回失效时，上 `sqlite-vec` 本地嵌入（构建期预计算，仍 BYOK），见 `申论写作AI辅助设计方案.md` A4

## 四、数据流与存储（对齐现有架构）

```
SQLite data/articles.db ── Vercel Function /api/* (只读，纯转发) ──► 前端
                                                        │
                              ┌─────────────────────────┼─────────────────────────┐
                              │                         │                         │
                      articleStore                annotationStore           shenlunStore/aiAssistStore
                 localEdits/deletedIds         materialType/mastery      paragraphSummaries/skeleton
                 contentCache LRU30            IndexedDB persist          IndexedDB persist
                              │                         │                         │
                              └────────── 导出/导入 JSON（含 shenlun） ◄──────────┘
                                                        │
                                              回流通道（见 3.4 阶段二/三）
```

- **本地优先不变：** 服务端不存用户数据，Key 存 `IndexedDB readbook:write-token`（BYOK）
- **回流需用户显式授权：** 脱敏（去原文偏移，仅留素材类型/主题/模板）+ 人工精选后才入公共池

## 五、壁垒如何变厚

| 阶段 | 形态 | 壁垒来源 | 依赖 |
|---|---|---|---|
| **阶段一：个人飞轮（已在 P1-P3/AI-1~AI-3 内闭环）** | 单用户“读→标→拆→背→导出→写”的历史复用：拆过的文章沉淀为个人模板库 | 切换成本：丢历史 = 丢半年积累 | 本期交付 |
| **阶段二：精选飞轮（运营飞轮）** | 周更 + 人工精选 10 篇样张/金句/句式模板，每周入库；用户开箱即得最新素材 | 供给频率 + 品味（时效性与精选质量，难抄） | 持续运营人力 + import 管线 P6 |
| **阶段三：众包飞轮（网络效应）** | 用户 opt-in 贡献脱敏素材/模板 → 聚合 → 去重/评级 → 回流为公共素材池/考点库 | 网络效应：用户越多，素材池越全，新用户冷启动越快 | 授权机制 + 审核 + 去重/质量分 |

> 不做阶段三也能成立：阶段一 + 阶段二已构成“**个人积累 + 持续供给**”的双飞轮，足以支撑小众付费。

## 六、衡量指标（北极星：周活用户的“可复用沉淀”）

- **供给：** 周更篇数、精选入库数、入库到可标可用时长
- **加工：** 人均周标注数、5 类分布、段意/骨架完成率、句式模板产出数
- **智能：** 预拆解采纳率、框架挂素材命中率、反向联想→存题转化率
- **沉淀：** 导出复用率、跨设备导入成功率、个人模板库 30 日留存
- **回流（阶段三）：** opt-in 率、贡献→精选入库率、公共池周活引用率

---

## 七、风险与取舍

- **版权：** 原文仅作“精读底本 + 标注锚点”，句式模板与人工拆解为衍生沉淀，降低原文依赖
- **质量：** 回流必经人工精选，不做自动全量入库，避免水化
- **隐私：** 默认本地，不回流；回流前二次确认 + 脱敏
- **成本：** 阶段二靠运营周更，阶段一/智能飞轮靠 BYOK，服务端零存储成本

## 八、与现有执行计划的对应

- P1 素材 5 类 + P2 段意/骨架 + P3 导出 = 加工飞轮底座
- AI-1 审题框架/AI-2 题型扩展/AI-3 预拆解/AI-4 反向联想 = 智能飞轮
- P6 外源入库 + 周更运营 = 原料飞轮
- 本文阶段一/二/三 = 壁垒演进顺序，不新增当期交付，仅明确回流与指标
