# 读本 READBOOK · 申论写作 AI 辅助设计方案

> 状态：**设计方案（评审稿）**
> 依据：2026-08-29 沟通（AI 辅助四场景讨论 → 用户确认范围）
> 定位：**AI 是素材与作答之间的桥**——不让 AI 凭空生成文章，而是拿读本已有的素材库和拆解记录当上下文，辅助审题与搭作答框架。
> 依赖：申论功能整合新方案.md 的 P1–P3（素材标记 / 拆解 / 导出）落地后启动。

---

## 一、范围裁定（用户已确认，2026-08-29）

| 讨论过的场景 | 裁定 |
|---|---|
| ① 审题立意 + 作答框架 | **纳入读本**（本方案核心） |
| ② 作答框架 × 素材库联动（每个要点挂素材卡片） | **纳入读本**（读本独有差异化，核心价值） |
| ③ 成文批改 / 打分 | **不做**——是另一个产品立意（判卷工具），与读本「阅读沉淀」定位不同 |
| ④ 段落升格 / 语言打磨 | **不做**——同上，属写作工具，另议 |

**题型范围**：申论不止大作文。覆盖五类题型——**概括、分析、对策、应用文、大作文**（与申论阅读处理设计方案.md §1.1 ② 的真题题型盘点一致）。不同题型的「作答框架」形态不同，见 §三。

---

## 二、核心思路

```
题干输入（+ 题型 + 12 主题）
→ AI 审题：题型要点 / 作答方向 / 字数与结构策略
→ AI 搭框架：按题型生成作答框架（要点清单 / 层次 / 对策条目 / 格式结构 / 总分论点）
→ 素材联动：框架每一项挂上素材库中可用的素材卡片（带原文出处）
→ 人工确认：采纳/编辑/删除后落库（不直接覆盖用户手填内容）
```

AI 的上下文 = 题干 + 主题筛选后的 annotationStore 四类素材 + shenlunStore 已拆解记录。素材库为几百条量级，**主题筛选 + 关键词匹配即可，不需要向量检索**。

### 双向链路（2026-08-29 补充，用户确认）

- **正向：题目 → 素材**（§三，AI-1/AI-2）：给题干找素材库里的可用卡片。
- **反向：素材 → 题目**（§五，AI-4）：读人民日报文章时反向联想申论考点/命题角度，各类题型都可以参考。
- 两端接起来是完整闭环：**读文章 → 反向联想考点（存下题干）→ 正向搭作答框架（挂素材）→ 写作**。素材库既是写作的原料，也是命题的镜子。

## 三、按题型的框架形态

| 题型 | AI 产出 | 素材联动重点 |
|---|---|---|
| 概括（≤200 字） | 要点清单（归纳维度 + 每条要点一句话） | 从材料相关文章的「论点/对策」卡片归纳表达 |
| 分析（≤300 字） | 层次分析（是什么/为什么/怎么办的拆解线） | 「论据·理论」卡片支撑分析角度 |
| 对策（≤450 字） | 对策条目（主体 + 做法 + 目的） | **「对策」类卡片是主战场**，可直接借用时评里的措施表述 |
| 应用文（≤500 字） | 格式结构（文种格式 + 内容模块提纲） | 对策 + 论点卡片填内容模块 |
| 大作文（1000–1200 字） | 立意方向 2–3 个 + 总论点 + 3 个分论点（每个一句话 + 论证角度） | 论点/论据/金句按分论点分组挂载 |

所有产出的结构都是**可编辑的清单**，不是一篇文章——读本只帮你「搭好架子、备好料」，成文自己写。

## 四、AI 预拆解（顺带项，归入本方案）

拆解面板加「AI 预拆解」按钮：对本篇时评一键生成 论点/论据/金句/对策/句式 候选标注 + 核心观点/分论点草案，**人工逐条确认后**才写入 annotationStore / shenlunStore。省逐句手标时间，同时反哺素材库（素材越多，§三的联动质量越高）。

**2026-08-30 扩展（决策 D15，范文精读）**：预拆解输出范围增加——

- **每段大意**：逐段一句话概括（候选写入 `ArticleStudy.paragraphSummaries`）；
- **结构骨架**：开头方式 / 主体层次 / 过渡 / 收尾（候选写入 `skeleton`，可由段意推导后再人工确认）；
- **可迁移句式**：从原文挑选可复用句，生成「原句 → 抽象化模板」候选（写入 `materialType:'pattern'` 标注的 `pattern` 字段）。

与既有候选同一交互模式：AI 只产候选，一律人工确认入库。

## 五、反向链路：素材 → 申论题目联想（AI-4）

> 2026-08-29 补充：可以通过申论找素材，也可以通过人民日报反向找题目，各类题型都可以参考。

### 5.1 入口与产出

| 入口 | 产出 |
|---|---|
| 阅读页右侧栏 / 拆解面板「申论考点联想」按钮 | 本篇文章的命题分析 |
| 摘录页素材卡片「联想考点」 | 单条素材（或本篇素材组合）可支撑的考点 |
| 素材合集导出页（可选） | 按主题出「本主题高频命题角度」 |

AI 输出（结构化清单，五类题型都可以给）：

- **可能的题干候选**：按 概括 / 分析 / 对策 / 应用文 / 大作文 各给 1–2 条（例：对策题「针对文中 X 问题提出解决建议（≤450 字）」；大作文「以‘……’为题写一篇议论文」）；
- **适配理由**：这篇文章为什么适合出这类题（结构特征：有对策段 / 有案例 / 观点鲜明）；
- **主题词与考点标签**：对应 12 主题 + 可提炼的规范表达。

### 5.2 闭环交互

1. 联想出的题干候选 → **人工确认后可保存**为一条「题目记录」（写入 aiAssistStore 的 question 模型）；
2. 保存的题目 → 直接进入 §三的正向流程「搭作答框架（挂素材）」；
3. 形成闭环：读文章 → 联想考点 → 存题 → 框架挂素材 → 写作；素材卡片与题目记录互相可跳转（题目页看它挂的素材，素材卡片看它被哪些题目引用）。

### 5.3 两个出题深度（2026-08-29 补充：根据文章生成题目可做）

| 深度 | 内容 | 形态 |
|---|---|---|
| L1 命题角度联想（§5.1 默认） | 从文章/素材联想到可能的考点与题干候选 + 适配理由 | 轻量：题干一句话清单，确认后存题 |
| L2 完整出题 | 按国考真题格式生成**完整题目**：【给定资料】（以本文/相关文章为底本改写成案例材料）+【作答要求】（五类题型任选，含字数与分值样式）+ AI 参考要点（可折叠，供写完对照；**不是批改**，只是出题附带的参考答案方向） | 重：一题一卡，存 aiAssistStore；素材卡片与给定资料保持出处关联 |

- L2 与「真题阅读模式」（解析国考 PDF）互为补充：真题是历史命题，L2 是**用素材库模拟出题**，都不进批改（A1 不变）。
- L2 产出同样走「生成 → 确认 → 入库」；给定资料以读本文章为底本生成时，保留与原文的跳转关系，方便对照。

### 5.4 与 AI 预拆解的关系

预拆解（§四）产出素材，反向联想（本节）消费素材，二者共用同一条 AI 基础设施（BYOK + Function 转发 + 客户端组装），仅 prompt 不同；建议 AI-3 落地后再做 AI-4。

---

### 6.1 调用链路（守住本地优先）

- 走 Vercel Function 转发（与现有 `/api/articles` 同款模式），服务端**只做纯转发**，不存任何用户数据。
- **上下文在客户端组装**：素材筛选、题干、拆解记录都在前端拼好放进 prompt 再发。
- **Key 管理（第一版 BYOK）**：设置页填自己的 API key，存 IndexedDB；无账号体系、无托管费用。体验验证后再议托管。

### 6.2 数据模型影响（全部可选、向后兼容）

| 产出 | 落点 |
|---|---|
| 审题结果 / 作答框架 | 新 store（暂名 `aiAssistStore`，key `readbook:ai-assist`）：按题干存 { question, questionType, topic, outline: OutlineItem[] }；OutlineItem = { text, materialIds[]（挂载的素材卡片）, adopted } |
| 采纳的分论点 | 一键写入 `ArticleStudy.subTheses`（大作文场景） |
| AI 预拆解 | 确认后写入 annotationStore（materialType 标注）与 shenlunStore，走既有 import 合并路径 |
| Prompt 组装素材 | 页面层 useMemo 过滤 annotationStore，不落新 store |

不变式：AI 产出永远走「生成 → 人工确认 → 入库」，不覆盖用户手填的拆解与素材。

### 6.3 Prompt 基线

固定基线：人民日报评论员文章风格 + 申论五类题型作答规范 + 字数约束；输出一律为结构化清单（JSON），前端渲染为可编辑卡片，禁止直接输出整篇文章。

## 七、实施顺序

| 步骤 | 内容 | 前置 |
|---|---|---|
| AI-1 | 审题立意 + 大作文分论点框架（含素材挂载、落库、BYOK 设置） | P1–P3 上线 |
| AI-2 | 题型扩展：概括/分析/对策/应用文的框架形态 | AI-1 验证后 |
| AI-3 | AI 预拆解（拆解面板按钮） | AI-1 基础设施 |
| AI-4 | 反向链路：素材 → 申论题目联想（五类题型，见 §五；L1 联想先行） | AI-3 落地后 |
| AI-4+ | 完整出题（真题格式：给定资料 + 作答要求 + 参考要点，见 §5.3 L2） | AI-4 验证后 |

## 八、决策点

| # | 决策点 | 结论 |
|---|---|---|
| A1 | 批改/打分是否做 | 否，另一个产品立意（判卷工具），不进读本 |
| A2 | 段落升格/仿写是否做 | 否，同上（写作工具），后续另议 |
| A3 | AI 产出是否直接写正文/覆盖拆解 | 否，一律「生成 → 确认 → 入库」 |
| A4 | 检索方式 | **默认不做向量检索/RAG**（2026-08-29）：素材几百条量级，主题筛选 + 关键词匹配 + 直接塞上下文即可。升级触发条件（满足其一再议）：① 素材超数千条、prompt 塞不下；② 题干与素材措辞差异大，关键词召回明显漏配（如题干说「基层治理」素材写「网格化管理」）；③ AI-4+ 完整出题需要在 517 篇全文中跨主题找底本。届时优先 sqlite-vec 本地嵌入（构建期预计算），仍走 BYOK，不引入独立向量服务 |
| A5 | Key 形态 | 第一版 BYOK（设置页自填），不托管 |
| A6 | 与 /practice 的关系 | 本方案的「题干 + 框架 + 素材」记录就是练习记录的最小形态；若 D13 后置的 /practice 启动，可直接复用 aiAssistStore 的数据模型 |
| A7 | 反向联想（素材→题目）覆盖范围 | 五类题型都给题干候选 + 适配理由；联想结果人工确认后才存为题目记录，与素材卡片双向可跳转 |
| A8 | 出题深度 | L1 命题角度联想先行，L2 完整出题（真题格式 + 参考要点）作为 AI-4+ 扩展；L2 附带的参考要点**不是批改**（A1 不变），仅供成文后对照方向 |
