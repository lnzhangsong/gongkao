## 一、形态：题目解析抽屉

- 入口：**作答要求整段收进题目抽屉**（阅读态正文只留材料 + 一张「在抽屉中查看题目」入口卡；编辑态仍在页面内联编辑）。题目抽屉（ExamQuestionsDrawer）列出全部题目，每题「解析」→ 打开该题思路抽屉；
- 抽屉复用拆解面板 `shenlun-panel` 骨架（桌面右侧 `min(600px, 94vw)` / 移动底部面板，类 `exam-draw` 覆盖宽度与内边距）；
- **`createPortal` 到 `document.body`**：真题页 `fade-in` 路由过渡会创建层叠上下文，`position: fixed` 会退化成相对定位（高度撑到内容长）——必须挂顶层；
- Escape / 遮罩 / 关闭按钮收起；打开期间锁正文滚动；
- 抽屉标题按题态：有答案「这道题的答案怎么来的」/ 无答案「这道题该怎么推导答案」。

## 二、双模式：溯源 / 推导（`src/lib/aiExamTrace.ts`）

同一数据结构与产出形态，按题目是否有参考答案切换 prompt：

| 模式 | 触发 | AI 任务 |
|---|---|---|
| **溯源** | `q.answer` 存在 | 把参考答案逐要点拆回材料：每条讲清「怎么想到 → 从哪句来 → 怎么加工」 |
| **推导** | 无参考答案 | 以命题人视角从材料**推导参考要点**：要点合起来就是参考答案，每条同样附思维路径与出处 |

产出门槛与解析（`parseTraceResult`）：mode 枚举容错（非法回退「归纳」）、sourceIdx 范围校验（越界回退 null=材料外）、think/quote/note 缺省可省。**A3 不变**：AI 结果先进页面草稿态，人工确认「保存入库」才写 store；手动「拆解」入口可直接逐条编写。

## 三、原文标注：行文思路 + 答题思路（`examMarks.ts` + `draftMaterialMarks`）

**主展示面在材料原文上（材料太长，思路要顺着材料读）**：材料区标题栏有「行文思路」开关（聚合全卷各题标注），打开后——
- 重要句高亮在原文里，**每句下方内联思路卡**：`第N题` 归属 + 行文思路（这句的作用）+ 答题思路（怎么用进答案）；
- 开关关闭 = 干净原文。抽屉「原文标注」列表与原文联动：点列表行跳到原文那句并闪烁。

针对本题，AI 从设问出发圈出相关材料里的重要句（6~15 条），每句标注：

- **行文作用（role）**：按 17 类体系词标注（`MARK_ROLES`）——内容作用：案例叙事/数据支撑/权威观点/民众声音/问题呈现/成绩成效/对策做法/原因分析/意义影响/危害后果；结构作用：背景铺垫/转折/递进/衔接过渡/总结收束；关键词：核心概念/高频关键词。AI 归一化到体系词（近义词映射），编辑下拉同源；
- **答题思路（use）**：每句必填（AI 漏填按「辅助句」兜底）——服务哪个设问、怎么用进答案；
- **重要性（level）双配色**：core 核心（accent 红，直接得分句）/ normal 辅助（hl-blue 蓝，结构背景句），高亮、内联思路卡色条、抽屉徽标三处统一。

渲染：引句做**空白不敏感匹配**（`findQuoteInMaterial`：去空白后找子串，字符映射回原偏移），命中片段在原文段落里包 `<mark class="exam-mark">`，悬停显示 行文/答题 思路。**标注只在该题解析抽屉打开时显示**（抽屉驱动，关掉即干净原文）；存 `QuestionMarks`（同 examStudyStore，`marks` 字段），AI 草稿 → 确认入库，列表可就地改写思路、删句。

## 五、数据模型（`src/stores/examStudyStore.ts`）

```ts
type DeriveMode = '摘抄' | '改写' | '提升' | '归纳' | '推理' | '补充'

interface AnswerPointTrace {
  id: string
  text: string             // 要点句（答案话）
  mode: DeriveMode         // 加工方式
  sourceIdx: number | null // 来源材料 idx；null = 材料外
  think?: string           // 思维路径：题干哪个词 → 定位哪则材料 → 怎么提炼（核心字段）
  quote?: string           // 原文摘句
  note?: string            // 加工说明：原文 → 答案话
}
// QuestionTrace { paperId, qIdx, origin: 'ai'|'manual', points, updatedAt }
// Record<`${paperId}#${qIdx}`, QuestionTrace>，idbStorage key `readbook:exam-study`
```

一条要点的展示叙事（正好回答「每句话怎么来、怎么思考」）：

```
① [mode 徽标] 要点句（答案话）
② 思路  题干要求「谈理解」→ 定位材料2小王的话 → 提炼「慢慢沉淀」理念
③ 材料2 ↖ 「原文摘句…」（点击跳材料锚点）
④ 加工  摘抄核心句 + 提升为规范表达
```

## 五、边界与决策

| # | 决策 | 结论 |
|---|---|---|
| M-1 | 溯源数据存哪 | 本地 IndexedDB（学习数据，与 shenlun 一致）；SQLite 迁移留后续 |
| M-2 | 思维/方法论的来源 | **只做针对题目的 AI 推导**（think 字段），静态方法论库废弃——通用方法未来若需回归，走独立文档/页，不再塞进真题流 |
| M-3 | 加工方式枚举 | 六类：摘抄/改写/提升/归纳/推理/补充 |
| M-4 | 无答案题 | 推导模式：AI 产出的要点即参考要点（含出处），不是批改（A1 不变） |
| M-5 | /assist 页 | 不加静态方法论卡（随静态方案一并移除）；审题立意本身就是针对题目的 AI 推导 |
| M-6 | 标注显示时机 | 抽屉驱动：打开哪题的解析，原文才高亮哪题的标注；不设全局常驻开关，避免多题标注混在一起 |
