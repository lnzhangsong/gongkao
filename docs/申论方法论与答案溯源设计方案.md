## 一、形态：底部面板（上下分栏）

- 入口：**作答要求整段收进题目抽屉**（阅读态正文只留材料）；题目抽屉列出全部题目，每题「解析」→ 打开该题解析面板；关闭解析面板时**自动带回题目抽屉**（避免「回不到题目」）；
- **桌面端为上下分栏**（2026-09-05）：面板贴底占屏幕下方（默认 52vh，`exam-draw` 类覆盖 `shenlun-panel` 定位），原文整宽在上、照常滚动（桌面不渲染遮罩、不锁滚动）；面板内要点列表独立滚动，内容版心居中；
- **移动端（≤640px）保持覆盖式底部抽屉**：遮罩 + 锁滚动（`useIsMobileViewport` 判断）；
- **拖拽调高**：面板顶缘把手（`usePanelResize`），范围 180px ~ 85vh，高度记忆到 localStorage（`readbook:exam-panel-h`）；
- **全屏按钮**：拉到 90vh（拖高把手暂时隐藏），再点恢复；题目切换时重置；
- 抽屉头动作区：**编辑（进入就地编辑，再点「完成编辑」即时保存）** / 全屏 / 关闭；「收起/展开」已移除（无中间态价值）；
- `createPortal` 到 `document.body`：真题页 `fade-in` 路由过渡会创建层叠上下文，`position: fixed` 会退化成相对定位——必须挂顶层；
- Escape 关闭；抽屉标题按题态：有答案「这道题的答案怎么来的」/ 无答案「这道题该怎么推导答案」。

## 二、双模式：溯源 / 推导（`src/lib/aiExamTrace.ts`）

同一数据结构与产出形态，按题目是否有参考答案切换 prompt：

| 模式 | 触发 | AI 任务 |
|---|---|---|
| **溯源** | `q.answer` 存在 | 把参考答案逐要点拆回材料 |
| **推导** | 无参考答案 | 以命题人视角从材料**推导参考要点**：要点合起来即参考答案 |

**每条要点教的是方法，不是结论**（2026-09-05 起 prompt 的两个重点字段）：

- `locate` **定位方法**：可复用的查找步骤——抓题干哪个关键词 → 判断去哪类段落找（问题段/对策段/案例段）→ 按什么信号锁定这一处（高频词/转折词/人物做法）。要求「拿到另一道题也能照着找」，禁止只说「定位到材料X」；
- `modeWhy` **加工判断**：为什么用这种加工方式而不是别的——对照原文说法与答案表述点出差距（口语vs书面 / 一处vs多处 / 具体vs规范 / 明说vs可推出）。

区块顶部另有「加工方式怎么选？」折叠速查（六类判断口诀）。**A3 不变**：AI 草稿生成后自动进入编辑态，顶部「完成编辑」即保存入库；「手动拆解」入口可逐条编写。

**要点卡的展示叙事（教方法的三步链 + 结果）**：

```
○ 定位  题干问「如何…」→ 对策题，先找对策段：政府文件/领导讲话出现的段落优先…
○ 材料  [材料1 ↖] 「原文摘句…」（点击跳材料锚点）
○ 加工  [提升] 原文"四预"已是规范短语，但整句是描述性的，答案需要「做法+对象」结构…
▍1  建设数字孪生黄河，构建"四预"智能管理体系   ← 链条终点，serif + accent 左边条强调
```

旧数据兼容：无 `locate/modeWhy` 的旧要点自动回退显示 `think/note`。

## 三、原文标注：行文思路 + 答题思路（`examMarks.ts` + `draftMaterialMarks`）

**主展示面在材料原文上**：材料标题行有「生成思路 ✦」按钮（材料级生成，qIdx = -材料idx；已有标注显示「重新生成思路」）；右栏阅读辅助面板有「行文思路」**常驻开关**（`readbook:exam-inline-marks`，记忆状态）——

- 开关打开：重要句高亮在原文里，**句后内联解析**（2026-09-05 定稿）：解析不换行、直接插在正文里，格式 `「辅助〈背景铺垫〉：引出话题…」`——等级药丸（core=accent 红实底 / normal=淡蓝底 / useless=灰底）+ 行文作用药丸 + 等级色小字解释，英文直角引号「」括起来；
- 高亮本身：透明底 + 2px 等级色下划线（`box-decoration-break: clone` 保证跨行连续），useless 灰色删除线；**无悬浮气泡、无手型光标**（解释已内联在句后，悬停只剩淡底色确认范围）；
- 从句末标点切断，解析紧跟该句；
- 开关关闭 = 干净原文。

AI 逐句标注（15~28 句 / maxTokens 8000）：**行文作用（role）** 按 17 类体系词（`MARK_ROLES`：案例叙事/数据支撑/权威观点/民众声音/问题呈现/成绩成效/对策做法/原因分析/意义影响/危害后果 + 背景铺垫/转折/递进/衔接过渡/总结收束 + 核心概念/高频关键词，AI 近义词归一化）；**答题思路（use）** 每句必填（漏填按「辅助句」兜底）；**重要性（level）** core/normal/useless 三档。引句**空白不敏感匹配**（`findQuoteInMaterial`），全卷标注聚合到各材料上渲染（`MarkedParagraph`）。

## 四、数据模型（`src/stores/examStudyStore.ts`）

```ts
type DeriveMode = '摘抄' | '改写' | '提升' | '归纳' | '推理' | '补充'

interface AnswerPointTrace {
  id: string
  text: string             // 要点句（答案话）
  mode: DeriveMode         // 加工方式
  sourceIdx: number | null // 来源材料 idx；null = 材料外
  locate?: string          // 定位方法（核心字段：教怎么找到这条）
  modeWhy?: string         // 加工判断（核心字段：教为什么这么加工）
  think?: string           // 旧字段，兼容保留
  quote?: string           // 原文摘句
  note?: string            // 加工说明（旧字段，兼容保留）
}
// QuestionTrace { paperId, qIdx, origin: 'ai'|'manual', points, updatedAt }
// traces: Record<`${paperId}#${qIdx}`, QuestionTrace>
// marks:  Record<`${paperId}#${qIdx}`, QuestionMarks>（材料级标注 qIdx = -材料idx）
// idbStorage key `readbook:exam-study`
```

`MaterialMark { id, matIdx, quote, role, use, level?: 'core'|'normal'|'useless' }`；删卷时 `removeForPaper` 级联清理孤儿数据。

## 六、边界与决策

| # | 决策 | 结论 |
|---|---|---|
| M-1 | 溯源数据存哪 | 本地 IndexedDB（学习数据，与 shenlun 一致）；SQLite 迁移留后续 |
| M-2 | 思维/方法论的来源 | **只做针对题目的 AI 推导**（locate/modeWhy 字段），静态方法论库废弃——通用方法未来若需回归，走独立文档/页，不再塞进真题流 |
| M-3 | 加工方式枚举 | 六类：摘抄/改写/提升/归纳/推理/补充（附判断口诀速查） |
| M-4 | 无答案题 | 推导模式：AI 产出的要点即参考要点（含出处），不是批改（A1 不变） |
| M-5 | /assist 页 | 不加静态方法论卡；审题立意本身就是针对题目的 AI 推导 |
| ~~M-6~~ | ~~标注显示时机~~ | **已修订**：不再抽屉驱动，改为「行文思路」**常驻开关**（右栏阅读辅助面板，状态记忆）；打开 = 全卷标注一起显示在原文（含句后内联解析），关闭 = 干净原文 |
| M-7 | 面板形态 | 桌面 = 底部上下分栏（不遮挡原文、正文可滚）；移动 = 覆盖式底部抽屉（遮罩 + 锁滚动）；可拖高、可全屏 |
| M-8 | 保存交互 | 编辑就地改、顶部「编辑/完成编辑」切换即保存；无底部保存按钮；AI 草稿生成即进编辑态 |
