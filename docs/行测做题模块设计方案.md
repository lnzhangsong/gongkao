# 读本 READBOOK · 行测做题模块设计方案

> 状态：**设计稿**（待用户确认范围后进入实施）
> 起草日期：2026-09-08
> 定位：在现有申论真题链路（`/exams`）之外，开辟**行测**做题模块——客观题刷题、对答案、错题本，并把错题挂进已有的复习算法（到期队列）。
> 入口归属：**挂载在既有规划的 Nav「练习」入口下**（`docs/申论功能整合新方案.md` P7 预留的「练习」入口、P5 的 `/practice` 申论练习记录）。练习 = 一个入口两条产品线：行测刷题（本方案，先做）+ 申论练习（P5，D13 后置，挂同一入口作二级 Tab）。
> 关联：`docs/学习与复习算法.md`（事件流底座、到期队列、FSRS 简化 R(t)——行测错题是复习算法最天然的输入源）；`src/stores/examStudyStore.ts`（学习数据 store + 云同步范式）；`api/exams.ts` + `data/articles.db`（papers/materials/questions 三表，行测需要平行的新表）。
> 与申论的关系：**平行模块，不复用卷库**。申论是主观题「读材料—写答案」，行测是客观题「刷题—对答案—复盘错题」，数据形状、交互、AI 用途完全不同，强行共用一张 papers 表只会互相牵制。

---

## 一、为什么做、做什么、不做什么

```
现有产品主线：读人民日报 → 攒素材 → 申论审题/思路/作答
行测的位置：  国考笔试 = 行测 + 申论，行测占分一半且纯客观题——
              它是「做题」属性最强的部分，天然适合刷题产品形态
```

| 目标 | 说明 |
|---|---|
| 刷题 | 按年份/卷别/题型/专项刷行测真题，客观题点选作答 |
| 对答案 | 提交即判分（答案客观唯一，无需 AI 批改），看解析 |
| 错题本 | 错题自动入本，按掌握度排期重做（接复习算法到期队列） |
| 数据资产 | 行测作答事件回流 learningEventStore，喂给素材推荐与复习排期 |

**明确不做**（与申论方案同款边界思维）：

- 不做模拟出题/题库生成——只收录真题，AI 只用于「解析理解辅助」，不生成题目；
- 不做拍照搜题、视频讲解；
- 一期不做数量关系之外的特殊题型交互（如图形推理的画布标注）——图形推理一期以图片 + 选项呈现，不做拖拽/画图。

## 二、核心设计

### 2.1 信息架构与路由

```
Nav 新增「练习」入口（即申论整合方案 P7 预留的那个）：
/practice             行测刷题（一期默认主页；顶部预留 Tab：行测 / 申论（P5 后置））
/practice/:paperId    行测试卷详情 = 做题界面（答题卡形态，非阅读页）
/practice/wrong       错题本（跨卷，按题型/掌握度过滤）
```

- 「练习」是一个**伞形入口**：一期只有行测一条线，Tab 结构先不渲染（避免空 Tab），仅当申论练习（P5）落地时升级为「行测 / 申论」双 Tab——届时行测内容平移到 `/practice/xingce`，`/practice` 做 redirect，无数据迁移成本。
- 与申论真题 `/exams/:examId`（阅读形态，材料长文 + 解析抽屉）刻意不同：行测详情页是**一屏一题或一屏一组**的答题卡形态，强调作答速度与节奏。

### 2.2 数据模型（新表，与 papers/materials/questions 平行）

SQLite（`data/articles.db`）新增三表，导入管线复用 `scripts/import-exams.mjs` 的模式：

```sql
-- 行测卷：一套卷 = 一场考试（副省级/地市级各一套，135/130 题）
CREATE TABLE xg_papers (
  id TEXT PRIMARY KEY,            -- guokao-xingce-2025-副省级
  year INTEGER NOT NULL,
  level TEXT NOT NULL,            -- 副省级 / 地市级
  title TEXT NOT NULL,
  duration_min INTEGER,           -- 官方时长 120 分钟
  total_points REAL,              -- 满分（国考官方未公布单题分，存 100）
  source_file TEXT NOT NULL UNIQUE,
  warnings TEXT,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 题目：行测没有「材料」层，资料分析的综合材料作为题组归属
CREATE TABLE xg_questions (
  paper_id TEXT NOT NULL REFERENCES xg_papers(id),
  idx INTEGER NOT NULL,           -- 卷内题号 1..135
  section TEXT NOT NULL,          -- 五大专项：常识判断/言语理解/数量关系/判断推理/资料分析
  subtype TEXT,                   -- 细分：逻辑判断/图形推理/定义判断/类比推理/片段阅读/逻辑填空/数学运算/资料分析…
  group_id INTEGER,               -- 题组 id（资料分析一篇材料带 5 题、图形推理一组）——NULL=单题
  group_stem TEXT,                -- 题组公共材料（资料分析图表文字/图形推理组说明）
  stem TEXT NOT NULL,             -- 题干（含转义的行内公式标记，见 §2.4）
  options TEXT NOT NULL,          -- JSON: [{key:"A",text:"…"},…] 数量 4-5
  answer TEXT NOT NULL,           -- "C"
  explanation TEXT,               -- 官方/机构解析（可为空，空则 AI 解析入口常开）
  points REAL,                    -- 单题分值（未知存 NULL，判分按对题计数）
  image TEXT,                     -- 题图（图形推理/资料分析图表）文件名，存 public/xingce/
  PRIMARY KEY (paper_id, idx)
);

-- 作答记录：本地优先 + 云同步（与 exam_study 同范式），不进 SQLite
-- 存 Supabase 表 xg_answers（结构见 §2.5）
```

要点：

- **题组（group_id）是一等公民**：资料分析一篇材料 5 小题、图形推理一图 5 题，展示与作答按组切分，判分按题。
- 选项与答案用 JSON/纯文本存，判分在前端完成（答案随卷下发即可判，无需后端判分接口；若担心开发者工具偷看答案，可后期改为判分接口，一期不做）。

### 2.3 刷题界面（答题卡形态）

```
┌────────────────────────────────────────────────────┐
│ 2025 国考行测 · 副省级      ⏱ 已用 43:12 / 120:00    │
│ ────────────────────────────────────────────────────│
│ [资料分析 · 材料四]  116-120 题                       │
│ ┌ 题组材料（图表 + 文字，可折叠）────────────────┐   │
│ └───────────────────────────────────────────────┘   │
│ 116. 2022年该省规模以上工业增加值同比增速为：          │
│   ○ A. 5.2%   ● B. 6.1%   ○ C. 7.4%   ○ D. 8.0%    │
│ 117. …                                              │
│ ────────────────────────────────────────────────────│
│ ← 上一组   [提交本组]   下一组 →     答题卡 ▦ 32/130 │
└────────────────────────────────────────────────────┘
```

- **两种模式**：考试模式（整卷计时、交卷才出分）与练习模式（每组提交即判、即时看解析）。默认练习模式。
- **计时器**：按卷时长倒计时，超时不拦截只标红——刷题产品的克制。
- **答题卡面板**（▦）：网格显示 130 题状态（未答/已答/对/错），点击跳题。
- 作答即写本地 store，刷新不丢（idbStorage 持久化，与 examStudyStore 同款）。

### 2.4 公式与图形

- 数学/资料分析的算式以**行内标记**存 `stem`（如 `$frac(1,2)$` 级别的极简标记或直接存纯文本近似式），一期渲染规则：纯文本 + 上标下标字符（²、₁），不引入 KaTeX——国考真题算式复杂度用文本可覆盖 90%。
- 图形推理/资料分析图表：导入管线裁图为 PNG 存 `public/xingce/{paper_id}/`，题目 `image` 字段引用；题组公共图存 `group_stem` 内引用。

### 2.5 作答数据与云同步

新 store `xingceStore`（范式完全对齐 `examStudyStore`）：

```ts
interface XgAnswer {
  paperId: string
  qIdx: number
  picked: string          // "B"；空串=未答
  correct: boolean
  seconds: number         // 本题耗时（练习模式下按进入题组到提交估）
  origin: 'exam' | 'practice'
  updatedAt: string
}
```

- 本地 IndexedDB（`readbook:xingce`），云同步表 `xg_answers`，接入 `cloudSync.ts` 新增 adapter——**拉取时校验形状**（`picked` 必须是 string、`correct` 必须是 boolean），吸取本次 `rec.marks` 事故的教训，坏数据拒入 store。
- 同步键 `paperId#qIdx`，无 traces/marks 双键问题，比申论侧简单。

### 2.6 错题本与复习排期（本模块的壁垒所在）

错题不是列表，是**队列**：

- 对答案时错题写入事件流（`learningEventStore.log('xingce-wrong', key)`），并按 `docs/学习与复习算法.md` 的到期队列进入复习排期：首次错 → 1 天后到期；重做对 → 拉长间隔（FSRS 幂律简化 R(t)）；连续两对 → 「已掌握」降权不再主动推。
- 错题重做 = 只渲染该题干与选项（答案置空），提交后回写 `xg_answers` 新纪录——同一题多条款记录都保留，排期算法看最近一条。
- 错题本页按「专项 × 到期状态」两个维度组织：今天该重做的排前面，按五大专项折叠。
- **与申论侧的联动**：行测事件流为 learnerProfile 贡献「学习密度」信号，供首页「本周阅读/练习」聚合展示——学习数据底座是同一个（`learningEventStore`），这是选它而非自建埋点的原因。

### 2.7 AI 辅助的克制用法

行测答案客观，AI 价值在「讲透」不在「判分」：

- **解析追问**：解析面板内置「让 AI 再讲讲」，针对该题题干+官方解析生成通俗拆解（存 aiAssistStore，范式同申论 AssistRecord，带 `paperId/qIdx` 关联）；
- **错因归纳**：专项错误率超阈值时，AI 汇总该专项错题共性（如「资料分析——基期量与现期量混淆」），一期仅文案，不做仪表盘；
- 不做 AI 出题、不做 AI 判分——客观题判分是确定性的，引入模型只会增加成本与错误面。

## 三、分期

| 期 | 内容 | 出口标准 |
|---|---|---|
| **X1 数据管线** | xg_papers/xg_questions 三表 + import 脚本 + 2024/2025 两年副省级、地市级 4 套卷入库（含题组与图片裁切） | `/api/xingce` 列表+详情接口返回 4 套卷，题目/选项/答案完整 |
| **X2 刷题闭环** | xingceStore + 列表页 + 答题卡详情页（练习模式：作答/判分/解析/计时/答题卡面板） | 130 题全流程可刷可判，刷新不丢作答 |
| **X3 错题本** | 错题队列接入复习算法到期排期 + `/practice/wrong` 重做闭环 + 云同步（含形状校验） | 错题次日出现在到期队列，重做答对后间隔拉长 |
| **X4 考试模式与 AI 解析** | 整卷计时交卷出分 + 「AI 再讲讲」 + 错因归纳 | 一套卷完整考试模式体验 |

X1-X2 是可用产品，X3 是留存壁垒，X4 是锦上添花。数据来源与申论真题同渠道（机构整理版 PDF/网页），导入脚本的清洗规则是 X1 的主要工作量。

## 四、数据质量与已知问题（2026 卷首批导入实录）

> 2026-09-08 首批导入 26 国考行测三套卷（数据源：`26国考行测+申论真题解析【26年】`）后记录。

| 问题 | 影响 | 处理 |
|---|---|---|
| **解析 PDF 是引流版**（页脚带"要成公，选优公"广告），只收录了部分题目详解 | 副省级 83 题、地市级 44 题、行政执法 1 题答案缺失 | 缺答案的题照常入库（answer 为 NULL），前端显示"暂无答案，未计分"；逐题记入 papers.warnings |
| **资料分析图表材料在 PDF 里是内嵌图片**（表格数据不在文本层） | 6 个题组（每卷 1-2 组）材料缺失，对应题目无法真正作答 | 尝试过 OCR（RapidOCR）回文字——表格数字识别率尚可但**存在误差且行聚类有错位**，2026-09-08 用户裁定回退；材料为空保留题目，等拿到带数据的题库源重新导入 |
| **图形推理/饼图选项题为纯图片形态** | 约 26 题题干与选项无法用文本表达 | 不收录，题号记录在 papers.warnings（如副省级 81–85、133） |

管线结论：`parse-xingce26.py`（PDF→JSON）→ `import-xingce.mjs`（入库）已跑通且可重复；
`xingce-ocr.py`（图表 OCR 回文字，含跨页材料与"—→一"识别修正）保留但默认不跑——识别质量不达刷题标准。
**换源即解**：任何带完整图表与答案的结构化题库（JSON 按脚本头 schema）放进 `data/xingce/` 重跑 import 即可，前端无需改动。

## 六、AI 辅助训练（答题模式增强，待设计）

方向：行测答案客观、AI 不参与判分，AI 的价值在**训练过程**——把"刷题"变成"带教练的刻意练习"。

| 能力 | 说明 | 接入点 |
|---|---|---|
| 讲题模式 | 提交后对错题生成个性化讲解：先问用户"你怎么想的"（选错的原因），再针对错因讲透，而不是甩一遍通用解析 | 判分后的解析区，已有 q.explanation 兜底 |
| 逼问式训练 | 对判断推理/言语题，AI 追问"题干哪句话支持你的选项"，训练定位论据的能力——申论方法论「溯源」思路移植到行测 | 答题中（可选开关） |
| 错因画像 | 按专项聚合错题，AI 归纳系统性弱点（如"资料分析——基期/现期混淆"），生成训练建议；数据源 xg_answers + 事件流 xingce-wrong | 错题本页 |
| 限时陪练 | AI 出同类题的变式题（基于真题题干改数字/改主体）加练——注意与"不做 AI 出题"边界的冲突，需用户裁定是否放开变式题 | 错题重做后 |
| 复习陪聊 | 到期重做时 AI 先用苏格拉底式提问引导回忆思路，再对答案 | 错题本到期队列（依赖 X3 排期） |

前置依赖：AI 配置（aiStore）已就绪；成本控制——讲解/逼问按次调用，错因画像按天聚合。
