## 一、P0 · 「开始阅读」入口固化（本次新增）

**现状**：首页入场卡永远打开同一篇文章。
`src/pages/HomePage.tsx`：

```ts
const featured = useMemo(() => articles.find((a) => a.featured) ?? articles[0], [articles])
```

`featured` 标记只有一篇（或落到 `articles[0]`），无论读到哪、哪天打开，「开始阅读」都指向它。

**方案对比**

| 方案 | 规则 | 优点 | 缺点 |
|---|---|---|---|
| A 顺序推进 | 取第一篇未开始/未读完的文章 | 符合「年编逐篇啃」的心智，进度可预期 | 每天打开是同一篇直到读完 |
| B 每日轮换 | 按日期哈希从未读池选一篇，当天固定 | 新鲜感 | 与年编顺序无关，积累感弱 |
| **C 混合（推荐）** | ① 有进行中的（`continueList[0]`）→ 继续阅读；② 否则取第一篇未读；③ 全部读完 → 从已读中随机复习 | 兼容三种使用状态，逻辑自然 | 实现略多（但 continueList 已有现成计算） |

**验收标准**

- [x] 连续两天打开首页，未产生任何阅读进度时，入场指向不变化（同一天内稳定）
- [x] 读过 3 篇后，入场指向第 4 篇未读（而非 featured）
- [x] 读到一半的文章出现在入场位时显示「继续阅读」语义
- [x] 首页 eyebrow 的假数据 `NO. 024` 同步替换为真实文章编号 / 当日日期

**修复**：

- 新增 `--accent-text` 令牌（`tokens.css`）：accent 的可读文本变体，小字专用

## 十、全站 UI 一致性审计（2026-08-31，仅审计先不改）

> 巡检范围：`tokens.css / base.css / home / library / reading / notes / settings / exam-preview / terms / assist` + 导航 / 弹窗 / 抽屉 / 工具栏 / 加载态
> 结论：全站存在两套并行的视觉语言尚未收敛——**A 直角墨线硬阴影**（`1px ink + 2px 直角 + 7px 8px 硬阴影 + ↗`，首页/文库/真题卡片）与 **B Bento 圆角柔边**（`14px/10px 圆角 + 发丝边 + 柔投影`，拆解卡/段意条/工具菜单）。后续收敛需先决策 B 是否作为正文内嵌卡特例保留。

### 1. 布局与版式

- **版心/内边距不统一**：首页 `32/38/54` / 文库 `32/38/65` / 设置 `38/38/80 gap60 1240px` / 阅读 `56/24/90 1244-1812px 三档` / 真题 `0/38/120` / 摘录三栏 `25/20-28`，底部留白 `54/65/80/90/120` 无阶梯。
- **页头四套**：Hero `clamp 65-140px` / 文库/设置 `46-82px` / 真题 `46-78px` / 阅读 `36-58px`，`subpage-copy max-width 300/300/340px` 不一致；阅读是唯一做 `1600/2400` 三档加宽的页面，4K 留白与其他页不一致。
- **栅格 gap**：`14px / 15px / 12px` 混用；`margin-top 28/44/72/52px` 混用。

### 2. 圆角 / 描边 / 阴影

- **圆角三档**：主语言 `2px` 直角 vs 工具类 `4px/6px` vs B 语言 `10px/12px/14px` vs 胶囊 `999px`，同一视口内 `2px` 卡片紧邻 `14px` 拆解卡割裂最明显。
- **描边两套**：`1px ink` 墨线（卡片/页头）与 `1px line` 细线（工具栏/搜索框）在文库页上下相邻。
- **阴影三套**：硬阴影 `7px 8px 0 ink` / 柔阴影 `0 12px 28px` / 偏移阴影 `4px 4px 0 accent 70%`；真题 hover `6px 8px 18%` 与首页 `7px 8px ink` 不一致。

### 3. 组件与控件

- **筛选签三套**：`.filter-pill 2px 反色` / `.terms-chip 2px 反色` / `.mat-chip 2px 彩底（hl-* 实色/半透明）`，选中态一为反色一为彩底，暗色下半透明与浅色实色不一致。
- **按钮五套以上**：`ghost 12px mono 34px` / `ink 实底 500 13-14px 36px` / `22px 方块` / `32px 4px` / `999px 胶囊` / `文字按钮`；删除三处 `exam-del 11px underline` vs `batch danger 12px 红框` vs `terms-del 11px` 不一致；主操作 `/assist ink+偏移阴影` vs `shenlun-save accent 实底` 主色相反。
- **搜索框三套**：`border-bottom 1px ink 220px` / `border 1px line 2px 240-260px` / `52px 4px`。
- **展开/收起三套**：`▸→▾ before` / `▸ rotate90deg` / `svg 180deg`。
- **下拉两套**：原生 `select 1px line` vs 自定义 `MenuSelect dashed 底线 / 1px line 框 36px`，暗色 `dark-ink` 与浅色 `ink` 混用。

### 4. 字型 / 字号 / 颜色

- **Mono 小字** `10/11/12/13px` 混用，`--label-size` 仅阅读/真题可调，其余写死。
- **字重字距**：阅读 `500 24px -0.02em` vs 卡片 `500 19-20px -0.01em` vs 精选 `600 28-53px -0.02em` vs 页头 `400 display 0.01em`，中文负字距 `-0.06em` 与 `-0.02em` 未全量统一。
- **颜色**：muted `color-mix 62%/65%/80%/85%` 无阶梯；危险色 `#b84b37` vs `#c0392b` 两值；`pick-a/b` 仅 `night/graphite` 定义；卡片小字部分已 `ink 80%` 中性化，部分仍 `muted`。

### 5. 面板与层级

- **侧栏三套**：阅读 `280px 透明 line` / 申论抽屉 `420px/92vw soft ink8%` / 摘录 `330px soft ink`，移动端 `78vh` vs `82vh` 不一致。
- **z-index 未收敛**：`shenlun 60/61` 硬编码（应为 `--z-drawer 110/120`），`modal 90` 与 `toolbar 90` 同级。
- **空状态三套**：`.empty-state 12px/2 serif` vs `.terms-empty 14px/1.9` vs `.shenlun-empty 12px/1.7 sans`。

### 6. 动效与交互

- 路由 `0.35s 淡入` vs 内容 `0.5s +12px 上浮`；卡片 `translateY -5px 0.35s` vs 规范词无位移；抽屉 `0.24s bezier 24px` vs 移动端 `32px` vs 工具菜单 `0.16s -6px scale`，缓动不统一；`reduced-motion` 未覆盖 `transform` 动画。

### 7. 响应式与断点

- 断点 `640/700/760/800/900/1050/1080/1600/2400` 八档，无统一栅格；`800-900` 区间导航已折叠但阅读侧栏仍显示，错位 100px。

> **🐛 已知问题（2026-09-02 记录，待复现与修复）：移动端阅读页菜单不可见。**
> 现象：窄屏（手机宽度）下进入文章阅读页，阅读辅助菜单（ReaderToolsPanel：阅读设置 / 申论拆解 / 拆解上屏等入口）不可见，用户无法打开申论拆解面板。
> 待查方向：① 阅读页工具区在窄断点下的显示/折叠逻辑（是否被 `display:none` 或移出视口）；② 与上述 `800-900` 断点错位问题是否同源；③ 修复时一并验证移动端申论拆解抽屉（`92vw` 宽）与「本文题目」入口的可达性。
> 优先级：高——移动端是碎片化阅读主场景，且该菜单是 AI-4 闭环（考点联想/本文题目）的移动端唯一入口。

### 8. 其他细节

- 图标 `svg` vs 字符 `↗/▸/▾/＋` 混用；分隔线 `solid ink / dashed 20% / solid line` 三套；表单聚焦 `accent 55%` vs `ink` vs `accent-text`；引用 `pullquote 2px accent` vs `exam-sheet 1px line+2px ink` vs `detail-note 2px accent`；编号 `accent-text 12px` vs `ink 13px` 不一致；触控热区仅部分小控件有 `::before -12px`。

## 十一、数据飞轮与壁垒优化建议（2026-09-01，仅审计先不改）

> 范围：对照 `docs/数据飞轮与壁垒设计.md` 的阶段一/二/三与 `申论写作AI辅助设计方案.md` A1–A8，审计当前代码实际落地程度。
> 结论：**学习链路科学、方向克制；但「飞轮/壁垒」目前只落地了飞轮的第一片叶子**。代码仅实现「读→标→拆→导出→框架写作」的线性个人积累（阶段一），回流（阶段二/三）零实现；真正的飞轮效应未发生，壁垒目前来自「切换成本」，而非结构性网络效应。
> 建议按 ROI 排序落地，全部先不动代码。

### 现状核实

| 规划项 | 代码现状 |
|---|---|
| 素材五类（D15）| ✅ `material.ts` 5 类 + `pattern`（句式带模板）|
| 拆解 + 范文精读 | ✅ `shenlunStore`（段意/骨架/句式确认链）|
| 审题立意 + 框架 + 素材联动 | ✅ AI-1 已落地（`AssistPage` / `aiAssist.ts` / `aiAssistStore`）|
| AI 预拆解（AI-3）| ✅ 已落地（2026-09-02，`aiPresplit.ts`，本节 2026-09-01 审计时未实现，现已过期）|
| 反向联想考点（AI-4 / AI-4+）| ✅ 已落地（2026-09-02，`aiExamGen.ts`，L1 联想 + L2 完整出题）|
| 精选回流 / 众包回流（阶段二/三）| ❌ 仅文档，零实现（`grep` 确认代码无回流通道）|
| 个人模板库 / 跨文章聚合 | ❌ `shenlunStore` 仅按 `articleId` 存，未抽聚合池 |
| 指标埋点（§六 9 类）| ❌ 无任何采集 |

### 优化建议（按 ROI 排序）

**1. 补齐「复用反馈」这条边（最高优先级，飞轮 vs 雪球的本质）**
素材被框架要点采纳、被导出/引用——这个「使用/采纳信号」目前完全没有回写到素材本身。没有它，数据只是「越滚越大」（雪球），不是「越滚越值钱」（飞轮）。
- 给每个素材回写 `useCount / lastAdoptedAt / qualityScore`（由框架采纳次数 + 导出/引用反推）；
- 该信号反向控制 AI-3 预拆解候选排序、框架挂素材推荐优先级；
- 这是让飞轮自转的引擎，优先级最高。

**2. 补 AI-3 预拆解 + AI-4 反向联想**
智能飞轮目前只转了半圈（AI-1 落地，AI-3/AI-4 未实现）。二者恰恰是**最能反哺素材库**的部分——AI-3 生成候选确认后入库、AI-4 存题。优先补 AI-3，它是「人工确认数据」的最大产地。

**3. 落阶段一「个人模板库」**
`paragraphSummaries / skeleton / pattern` 全锁在单篇里。阶段一承诺的「拆过的文章沉淀为个人模板库」是**跨文章聚合视图**，目前缺口。缺它，阶段一的切换成本没立住。至少加「我的句式/骨架模板」聚合池，把 pattern 与 skeleton 从单篇抽出。

**4. 写作出口不止「导出 Markdown」**
D13 主线「素材×写作」的最后一跃是断的。补一个轻量「写作工作台」——贴题目 → 用分论点组织 → 素材一键插入；不做批改（A1 不变），只做组装，避免用户导出完就离开。

**5. 句式模板（pattern）壁垒资产化**
它是衍生物里最难被爬、迁移价值最高的一环（回答「换个主题怎么写」）。阶段二精选应把「句式模板库」当星品单独立出运营，比精选原文金句壁垒更高。

**6. 加轻量埋点**
§六 9 类指标已定义但零采集。先加轻量埋点：素材标注数、框架采纳率、句式模板产出数、导出复用率，用以判断飞轮哪一环断了。

**7. 众包（阶段三）先低门槛验证意愿**
脱敏+审核+去重+质量分是完整运营管线，但小众工具 opt-in 池子很可能太小。先做「用户贡献一个句式模板即可导出案例集」验证有人贡献，再建管线。

**8. 用 AI 降阶段二运营成本**
阶段二靠人工周更精选，是持续人力成本。可复用同一条「AI 生成候选 → 人工确认」不变式，让 AI 先从周更里挑候选、人工只确认，降低运营门槛。

### 一句话结论

学习方式本身成立（读→标→拆→背句式→写，符合申论「积累→规范表达→谋篇」规律）；设计作为阶段一→二→三的演进路线正确；但别把「壁垒」的功劳记在尚未发生的回流上——先让阶段一+二的「读→标→拆→写」被真实用起来，数据越多越离不开，才是眼下该守住的。
