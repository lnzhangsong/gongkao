## 一、现状与缺口

```
现有链路（已落地）：
读文章 → 标素材 → 拆解 → 背记 → AI审题+框架（AssistPage）→ 真题思路推导（M1）→ ❓
                                                                      ↑
                                                        缺口：思路之后，答案在哪里写？
```

| 环节 | 现状 | 缺口 |
|---|---|---|
| 审题立意 | AssistPage AI 审题 + 框架，落库 AssistRecord | 框架与真题题目**没有关联**（AssistRecord 无 paperId/qIdx） |
| 思路 | 真题页 M1 思路推导，QuestionTrace.points 存了逐条要点 | 要点只是「想过的」，没有「写了的」与之对照 |
| **作答** | **无输入区、无字数仪、无任何辅助** | 本方案主体 |
| 复盘 | 无 | 写完答案后没有「漏了哪些要点、素材用没用上」的回路 |

核心判断：**写答案的辅助不需要新的 AI 能力，需要的是把已有数据在作答时刻重新组织**。要点清单（traces）、素材卡片（annotations）、作答框架（AssistRecord）、字数要求（ExamQuestion.wordLimit）都已经在库里。

## 二、核心设计：答题卡（Answer Sheet）

### 2.1 位置与形态

落在 **ExamPreviewPage** 每道题下方（M1 解析面板旁），点击「写答案」展开：

```
┌──────────────────────────────────────────────┐
│ 作答区（textarea，随内容增高；纸感样式与阅读页一致）      │
│                                              │
├──────────────────────────────────────────────┤
│ 328 / 400 字 ▓▓▓▓▓▓░░  ↑ 未用要点 2 条 · 引用素材 1   │  ← 字数仪 + 实时对照条
├──────────────────────────────────────────────┤
│ 折叠侧栏：要点清单（每条可点「写到了」）/ 素材回声卡      │
└──────────────────────────────────────────────┘
```

- 自动保存（防抖 2s，写入 examStudyStore，云同步自动继承——`exam_study` 表 kind 增加 `'answer'`，无新表）
- 无 AI 依赖：P1 全部离线可用

### 2.2 四路已有数据的作答时刻重组（P1/P2）

| 辅助 | 数据来源（全部已有） | 交互 |
|---|---|---|
| **① 字数仪** | `ExamQuestion.wordLimit` | 实时字数（中文字符计）+ 进度条 + 超/欠阈值变色（±10%） |
| **② 思路对照** | `QuestionTrace.points`（M1 要点，含 mode/sourceIdx） | 要点清单逐条可勾「写到了」；也可从作答文本做**包含匹配自动点亮**（要点句去停用词后的关键词命中率 ≥ 阈值）。收尾显示「漏答 2 条：…」 |
| **③ 素材回声** | `annotationStore`（按题干主题过滤）+ `learnerProfile` 回声排序（快忘的、同主题已拆的优先） | 侧栏 3-5 张素材卡，点击插入光标处（以「引用」样式带出处）；用过的素材在卡上打勾（文本包含匹配） |
| **④ 框架支架** | `AssistRecord.outline`（AssistPage 已产出的框架） | 题型相同时一键把框架条目铺成作答骨架（每条一行占位，逐条填充）；AssistRecord 与真题的关联靠题干文本匹配 + 手动绑定（P1 手动，P2 建议） |

### 2.3 自评辅助（P3，AI 介入的唯一位置）

对照参考答案（`ExamQuestion.answer`，仅 `answerMatched` 的题）与 AI 完整出题的 `referencePoints`：

- 产出物是**三列对照清单**：我的答案分句 ↔ 参考要点 ↔ 命中判定（命中/部分/遗漏）
- 每条遗漏要点给一行提示：「M1 思路里有这条：…（回看溯源）」
- **不给分、不评语言**（守住 D-ruling ③ 边界）；语言打磨属「段落升格」，仍维持不做
- 调用形态与 AI-2 相同：BYOK、生成候选 → 人工确认

### 2.4 数据模型（向后兼容）

`examStudyStore` 增加一个 Record（与 traces/marks 并列，persist 自动带上）：

```ts
answers: Record<string, AnswerDraft>   // key = traceKey(paperId, qIdx)
interface AnswerDraft {
  text: string
  updatedAt: string
  checkedPoints: string[]        // 手动/自动点亮「写到了」的要点 id
  usedAnnIds: string[]           // 引用过的素材卡
  selfCheckAt?: string           // 最近一次自评对照时间
  selfCheck?: { hit: string[]; partial: string[]; miss: string[] }
}
```

- 云同步：`exam_study` 表 kind 联合类型加 `'answer'`，零新表
- 事件流：首次成文记 `answer-write`（新 kind，同日去重）、自评完成记 `answer-check`——learnerProfile 无需改结构即可消费
- 复盘视图（P3）：真题列表页加「已作答 X 题 / 漏要点 top 主题」小统计（数据全部来自现有事件流）

### 2.5 批改打分（P4，2026-09-07 用户裁定纳入）

推翻原裁定③：在自评对照（P3）之上叠加**结构化评分**。

- **评分维度**（按申论阅卷惯例拆维，不给笼统总分）：
  - 要点完整度（对照参考要点，P3 的命中数据直接复用，占 40%）
  - 条理与结构（分层/总分逻辑，AI 按作答文本结构评估，占 25%）
  - 表达规范（语言凝练度、卷面用语，占 20%）
  - 字数与格式（wordLimit 达标度，纯规则计算，占 15%）
- **产出物**：四维雷达 + 每维一句话诊断 + 逐句批注（表达问题句高亮，附改进建议候选 → 人工确认后可替换）
- **素材维度加分项（读本独有）**：统计作答引用素材卡的占比与类型分布，提示「对策类素材 0 引用」这类结构性建议
- 前置依赖：P3 的三列对照与素材引用统计；仅对 `answerMatched` 题或 AI 出题（有 referencePoints）的题开放
- 分数只存本地与云端（`AnswerDraft.selfCheck` 扩展为 `score` 对象），**不排行、不对比他人**

## 三、分期

| 期 | 内容 | 特征 |
|---|---|---|
| **P1 答题卡** | 作答区 + 字数仪 + 思路对照（手动勾选 + 自动点亮）+ 自动保存 + 云同步 | **零 AI、纯已有数据** |
| **P2 素材回声** | 素材卡注入与「用过」标记、框架支架铺开、AssistRecord↔真题手动绑定 | 把 AssistPage 和真题页打通 |
| **P3 自评辅助** | 参考答案三列对照 + 漏点回看溯源 + 复盘统计 | AI 介入第一层：对照不打分 |
| **P4 批改打分** | 四维评分 + 逐句批注 + 素材维度诊断（2026-09-07 新纳入） | AI 介入第二层：结构化评分，非总分判卷 |

## 四、刻意不做（维持既有裁定）

- 语言润色升格 / 段落改写代笔（裁定④，属写作工具；P4 的逐句批注只提示问题与方向，不代写）
- 真题页内做富文本编辑器（申论答题练的是内容与字数感，纯文本足够；格式化是写作工具的事）
- 强制绑定：不用 AssistPage 生成框架也能完整答题

## 五、验收

- P1：读一篇→推思路→写答案→字数仪变色→勾要点→刷新不丢→换设备登录答案在（云同步继承）
- P2：答题卡侧栏出现回声素材，插入后卡面打勾；AssistPage 框架可铺进作答区
- P3：对 `answerMatched` 的题出三列对照，遗漏要点可跳回 M1 溯源；不打分
